🔍 Key Insights & Recommendations

✅ What Went Well

  • First 5,000 VM target achieved — Run 4 created all 5,000 VMs, demonstrating the infrastructure can handle the full load
  • 100% CRP success rate — Every VM PUT accepted by CRP returned HTTP 201 across all 3 parallel runs
  • 100% DiskRP disk creation success — All 14,820 disks in Run 4 (and all disks across all runs) created successfully
  • Zero SRP throttling — No HTTP 429s across 76K+ PutStorageAccount operations
  • DNS Pool 100% hit rate — Pre-provisioned pool fully served demand with zero misses
  • ARM latency improving — Overall avg latency dropped 49% (648ms → 328ms) and P95 dropped 69% across runs
  • ARM NIC throttling decreasing — NIC PUT throttles dropped 25.5% (56.6K → 42.1K) with retry ratio improving from 29× to 19×
  • Consistent throughput improvement — ARM VM PUT rate increased from 74/2min to 192/2min (+159%)

⚠️ Areas for Improvement

  • ARM NIC PUT throttling is the #1 bottleneck — 42K+ HTTP 429 responses for 5K NIC creates (18.8× retry ratio). This is the primary reason deployment takes ~97 min instead of 5 min
  • OSProvisioningTimedOut — 177 VMs (1.77%) experienced guest agent timeout. VMs are created but marked failed by ARM
  • ARM VM PUT P99 tail latency — Increased from 2,798ms (Run 3) to 4,367ms (Run 4) — expected at higher volume but worth monitoring
  • Deployment wall clock time — ~97 minutes vs the 5-minute target. ARM throttling + parallel copy loops + OS provisioning are the bottleneck

📌 Recommendations

  • Use VMSS instead of individual VMs — VMSS creates NICs internally, bypassing per-NIC ARM throttling. This alone could reduce deployment time dramatically
  • Request ARM throttling limit increase — Contact ARM team to increase NIC PUT rate limits for this subscription/region for scale testing
  • Pre-create NICs — Create NICs in a separate prior deployment, then reference them in VM creation to avoid NIC throttling during VM burst
  • Increase OS provision timeout — Raise ARM timeout to reduce OSProvisioningTimedOut failures
  • Infrastructure is not the bottleneck — CRP, DiskRP, and SRP are all performing within SLA. ARM's per-resource throttling is the constraint
