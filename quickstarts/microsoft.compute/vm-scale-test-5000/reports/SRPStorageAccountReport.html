DNS Pool Mechanism: DiskRP maintains a pre-provisioned pool of storage accounts with DNS names already registered. When a disk is created, DiskRP calls CreateStorageAccount:
• 200 (Hit): SA already exists in the pool — instant allocation, no DNS wait
• 202 (Miss): New SA must be created — triggers async provisioning + DNS registration (~17s P50)
• IdempotencyKey requests: Pool-managed (pre-provisioned) path
• Non-IdempotencyKey requests: Direct creation path (always 202/miss)

Good news for PremiumV2: The pre-provisioned DNS pool hit rate for PremiumV2_LRS is 100% in both runs. All 8,868 (parallel) and 8,294 (serial) pool-managed SA requests hit an existing account instantly — zero cold DNS creation on the critical path.
Concern: ~27,000 CreateStorageAccount calls per run go through the non-IdempotencyKey (direct creation) path with 0% hit rate. Each of these triggers a full async SA provisioning + DNS registration cycle (~17s P50). These appear to be for OS disks and non-pooled SKU types. This is a significant source of latency if it's on the critical path.
