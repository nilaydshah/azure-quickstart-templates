Analysis & Findings

What Improved

1. Throughput: Peak PUT rate increased 74% (395 → 687 per 2-min window). All VMs were submitted to CRP within ~35 minutes vs ~4 hours in serial mode.

2. Total VMs Created: 363 more VMs created (4,219 vs 3,856). Parallel mode gets more work done before hitting any timeout or quota limits.

3. Test Duration: Complete test window was ~2.8 hours vs ~4 hours — a 30% reduction in wall-clock time.

What Got Worse

1. CRP E2E Latency: P50 jumped from 9.1s to 22.0s (+142%). This is expected — higher concurrency means more VMs competing for host resources during OS provisioning. P99 spiked to 99s (from 39s).

2. OS Provisioning Timeouts: Increased from 7 to 12 (+71%). More concurrent VMs = more hypervisor contention = more timeout risk.

3. XStore DeleteCorLink P99: Jumped from 1,050ms to 2,840ms (+170%). Higher concurrent load on cleanup path creates tail latency.

What Stayed Stable

1. DiskRP: 100% success, identical P50/P99 latency. DiskRP handles the load perfectly regardless of concurrency level.

2. CRP Sync Latency: P50 increased only 15% (466→538ms). The synchronous CRP processing is well-scaled.

3. XStore Creation Path: CreateContainer, SetInternalProps, WritePages — all 100% success with no latency degradation.
