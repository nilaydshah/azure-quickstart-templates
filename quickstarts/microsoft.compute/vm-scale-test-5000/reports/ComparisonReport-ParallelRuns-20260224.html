🎯 Key Insights & Recommendations

Improvements Across Runs

  1. NIC throttling reduced 57% (56K→24K) — ARM platform improvements or natural load patterns
  2. Wall clock improved 35% (97→63 min) — direct result of fewer NIC retries
  3. DiskRP now error-free for 2 consecutive runs — reliability improving
  4. Disk completion at 100% — Run 5 created all 15,000 disks (first time at perfect count)
  5. CRP sync P95 improved 60% (1,317ms→791ms) — CRP processing getting faster

Areas of Concern

  1. VM PUT throttling emerged — 2,144 429s in Run 5 (vs 149 in Run 4). ARM may be shifting throttle targets.
  2. CRP E2E P95 increased — 87.9s in Run 5 vs 34.4s in Run 4. Long-tail provisioning is growing.
  3. Pool Manager async allocations — 32 in Run 5 vs 1 in Run 4. DNS pool may need expansion for scale.

📎 Appendix: Kusto Queries

Q1 — ARM Operation Summary

// Cluster: armprodgbl.eastus.kusto.windows.net | Database: ARMProd
Unionizer("Requests", "HttpIncomingRequests")
| where PreciseTimeStamp between (datetime(START) .. datetime(END))
| where targetUri contains "TDPR-RG-{rg}"
| where operationName !contains "GET"
| extend opType = case(operationName contains "VIRTUALMACHINES", "VM PUT",
    operationName contains "NETWORKINTERFACES", "NIC PUT", "Other")
| summarize total=count(), succeeded=countif(httpStatusCode >= 200 and httpStatusCode < 300),
    throttled=countif(httpStatusCode == 429), callbacks=countif(httpStatusCode == -1) by opType

Q2 — CRP VM PUT with E2E Latency

// Cluster: azcrp.kusto.windows.net | Database: crp_allprod
ApiQosEvent
| where subscriptionId == "b883903d-216e-45b3-98b0-058819ec9224"
| where resourceGroupName in~ ("TDPR-RG-{rg}")
| where operationName == "VirtualMachines.ResourceOperation.PUT"
| summarize totalVMs=count(), http201=countif(httpStatusCode == 201),
    avgSync=avg(durationInMilliseconds), p50E2E=percentile(e2EDurationInMilliseconds, 50),
    p95E2E=percentile(e2EDurationInMilliseconds, 95)
