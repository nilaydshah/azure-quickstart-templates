🔴 Root Cause: ARM NIC PUT Rate Limiting

ARM applies per-subscription write throttling. When 20 parallel deployments simultaneously create 250 NICs each (5,000 NIC PUTs + dependents), ARM's rate limiter triggers HTTP 429 responses on ~45% of NIC requests. Each 429 forces a client retry with exponential backoff, creating a cascade:

  1. 20 batches fire simultaneously → massive NIC PUT burst
  2. ARM throttles NIC PUTs (429) → retries queue up
  3. NIC creation stalls → VM PUT blocked (depends on NIC)
  4. Batches complete in waves every ~18 min as throttle windows clear
  5. 97 min total instead of ~15 min theoretical

1Stagger batch deployments — Launch batches in 4 waves of 5 (1-min spacing) instead of all 20 simultaneouslyReduce NIC 429s by ~60-80%Low
2Pre-create NICs — Deploy NICs in a separate template before VMs, then reference existing NICsEliminate NIC throttling entirelyMedium
3Use VMSS — VMSS handles NIC creation internally, bypassing ARM per-resource throttling~5-10× faster deploymentHigh (different template)
4Request ARM throttle increase — Contact ARM team for subscription-level write limit raise2-3× more NIC PUTs before throttleMedium (process)
5Reduce concurrent NIC PUTs — Use ARM template copy mode "serial" for NICs only, parallel for VMsMay increase wall clock slightly but reduce retriesLow
